## 实际运行结构

Nginx 监听公网 80，转发到服务器本机 127.0.0.1:8000 的 FastAPI。FastAPI 同端口提供 Vue 生产构建与 /api。systemd 的 youlian 和 nginx 均为 enabled、active。联系人库固定在 /var/lib/youlian/contacts.sqlite3，应用版本在 /opt/youlian/releases，当前版本由 current 符号链接指向。

初次部署代码版本为 bcb540bf40f8538e1dfbceddaf13e51f23202cbb。后续提交补充验收文档和证据，未修改已部署的功能代码。

## 已完成的公网验证

- 从本机直接请求公网 /api/health，Nginx 返回 HTTP 200、status=ok。
- 标准 Chromium 直接打开公网地址，加载实际部署的 Vue 构建；请求真实云端 API。
- 从空演示库新增一位联系人，包含两条电话、一条邮箱、一条社交账号及一条地址；验证前导零、国际号码及分机保存。
- 编辑姓名和第二条电话，方式数量不累积；搜索社交账号可找到联系人。
- 收藏、收藏筛选、取消收藏及再次收藏均正确，服务端状态保存。
- 从网页下载真正的 .xlsx 导出文件与模板；正常样例导入新增 4 人，错误 JSON 文件显示第 2 行与 Phone 列错误且整批不写入。
- 390px 窄屏列表和新增弹窗无水平溢出。
- 真正停止并启动云端 youlian 服务，刷新后数据、收藏和多联系方式保留。
- 网页确认删除后返回 204；清空本次虚构演示数据，再导入刚才导出的 Excel，恢复一位联系人及全部五条方式与收藏。
- 浏览器无页面脚本错误。Excel v1 的 label 不参与往返，与接口格式说明一致。

## 服务器整机重启

执行 SQLite 在线备份后，真正重启 Ubuntu 服务器。重启前后 boot_id 不同，Nginx 和 youlian 均自动恢复为 active、enabled；公网健康检查恢复 200。读取的 5 位联系人完整 JSON 与重启前一致，包括收藏和全部联系方式。该检查独立于服务进程重启检查。
